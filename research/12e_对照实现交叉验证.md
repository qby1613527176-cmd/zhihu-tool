## 0. 一行结论

**生态已收敛出同一条信任链：`d_c0` 预热 → `x-zse-96` 签名 → `__zse_ck` 挑战 → 40362 只剩「换身份（新匿名会话/住宅IP/登录态）」一条路；且 2026 年的新实现（zhihu-proxy）已证明「Node vm 手写桩」可替代 jsdom，沙箱内 XHR 一律桩死、cookie 只靠 `document.cookie` setter 捕获——与我方 T5 设计同构，可直接抄其四个文件。**

## 3. 各家拆解与可抄代码模式

### 3.1 cv-cat/ZhihuApis —— jsdom + 官方 webpack 全量包

**架构**：Python (FastAPI) 管 HTTP，`execjs` 内嵌 Node 跑 `static/zhihu.js` 算签名。cookie **完全不自铸**——README 要求用户浏览器登录后 F12 复制 Cookie 头传入。

**沙箱构造**（`static/zhihu.js` 头部，可抄的反检测补丁三件套）：

```js
const jsdom = require("jsdom");
const { JSDOM } = jsdom;
const dom = new JSDOM(`<!DOCTYPE html><p>Hello world</p>`, {url:"https://zhuanlan.zhihu.com/"});
window = dom.window; location = window.location; navigator = window.navigator;
document = window.document; history = window.history; screen = window.screen;
// 补丁①：constructor.name 检测对抗
let xxx = Object.prototype.toString
Object.prototype.toString = function () {
    if(this.constructor.name === 'Document') { return '[object HTMLDocument]' }
    else if(this.constructor.name === 'CanvasRenderingContext2D') { return '[object CanvasRenderingContext2D]' }
    return xxx.call(this, arguments)
}
// 补丁②：藏 jsdom 内部属性
window._resourceLoader = undefined
window._sessionHistory = undefined
// 补丁③：native code 伪装
let aaa = Function.prototype.toString
Function.prototype.toString = function () {
    if(this.name === 'Window') { return 'function Window() { [native code] }' }
    return aaa.call(this, arguments)
}
const zc = require('./static/other')   // ← 3.7MB 知乎官方 heifetz 包
```

- `package.json` 额外依赖 **`canvas: ^2.11.2`** —— 官方 JS 会读 canvas 指纹，用 node-canvas 补。
- **XHR 处理**：jsdom 只提供环境，签名函数 `tv()` 是纯计算；所有网络请求在 Python 侧 `requests.get` 发出。**沙箱 XHR 问题在架构层面被绕开**（JS 从不发请求）。
- 签名核心（`zhihu.js` 尾部，与官方算法一致）：

```js
function tv(er, eo, ei, ec) {
    var eu = ei.zse93, ef = ei.dc0, ed = ei.xZst81
    var em = [eu, e8(er), ef, ti(eh) && eh, ed].filter(Boolean).join("+");
    //            zse93  path+search  d_c0  body      xZst81
    return { source: em, signature: encrypt(md5(em)) }
}
// 外部: x-zse-96 = '2.0_' + res['signature']
```

- **生产可用性**：FastAPI + Dockerfile + uvicorn，「能用」级；但无预热、无风控重试、无挑战求解——数据中心 IP 上裸跑 API 会被 40362 拦，它没处理。

### 3.2 HGXY2004/zhihu-proxy —— vm 手写桩派，唯一有完整风控信任链

**四层架构**（README 自述），每层都有可抄实现：

**① 会话预热（session.mjs）——「先访问首页建立档案」的标准动作实证**：

```js
/** 匿名预热：访问 /explore 获取 d_c0 等设备 cookie */
async warmup({ force = false } = {}) {
    if (!force && this.dC0) return true;
    await this.throttle();
    const res = await fetch('https://www.zhihu.com/explore', {
        headers: { 'User-Agent': UA, 'Accept': 'text/html,...', 'Accept-Language': 'zh-CN,zh;q=0.9' },
        redirect: 'manual',
    });
    this.anon.absorb(res);           // d_c0/_zap/BEC 落罐
    saveJson(SESSION_FILE, { cookies: this.anon.entries(), ... });  // 持久化
}
async ensureReady() { if (!this.dC0) await this.warmup({ force: true }); }
```

**② x-zse-96 签名（sign.mjs）——jsdom 的可替代方案（重点可抄）**：

```js
const sandbox = {
    document, location, navigator,           // 全部是手写桩对象，非 jsdom
    history, screen, performance,
    sessionStorage: { setItem: noop, getItem: () => null, removeItem: noop },
    localStorage:  { /* 同上 */ },

    atob: (s) => Buffer.from(s, 'base64').toString('binary'),
    btoa: (s) => Buffer.from(s, 'binary').toString('base64'),
    setTimeout: (fn, ms, ...a) => setTimeout(fn, Math.min(ms||0, 1000), ...a),  // 钳制定时器
    crypto: { getRandomValues: (arr) => ..., subtle: {}, randomUUID: () => 'xxx...' },
    // ...
};
sandbox.window = sandbox; sandbox.self = sandbox; sandbox.globalThis = sandbox;
vm.createContext(sandbox);
vm.runInContext(otherSrc, sandbox, { timeout: 30000 });    // cv-cat 同款 3.7MB 官方包

// 签名: sandbox.tv(url, body, { zse93: '101_3_3.0', dc0, xZst81: null }, '')
```

性能：加载 ~100ms（进程级单例），单次签名 <1ms。**零 npm 依赖**。

**③ __zse_ck 挑战求解（zseck.mjs）——沙箱 XHR 处理的标准答案**：

```js
// 沙箱里 fetch 直接桩死——挑战脚本的所有产出只靠 document.cookie setter 捕获
fetch: () => Promise.reject(new Error('sandbox fetch blocked')),

// document.cookie setter 是唯一出口
let cookieStore = '';
Object.defineProperty(document, 'cookie', {
    get: () => cookieStore,
    set: (v) => { captured.cookies.push(String(v)); /* ...更新 cookieStore */ },
    configurable: true,
});

// 求解结果: __zse_ck = __g.ck + '-' + metaContent
// fetchWithChallenge: 403 HTML 挑战页 → 抠 meta + 挑战JS URL → 下载官方JS(带缓存)
//   → vm 沙箱跑 → cookie 进 jar → 带罐重试, maxAttempts = 3
// 关键判据: `if (!ctype.includes('html')) break; // JSON 风控错误(40362)等，挑战求解无济于事`
```

产出 cookie **直接进 CookieJar 复用**（不再过第二道），并写回匿名会话层持久化。

**④ 40362 对策（session.mjs + README 能力边界表）——全生态唯一明确记载**：

```js
// 风控码（40362 请求异常限制 / 10003 参数异常）→ 换新匿名会话 + 退避重试
const retryable = (x) => x.riskControl && !x.needLogin && !x.ok &&
    [40362, 10003].includes(x.json?.error?.code ?? -1) || (x.status === 403 && ...);
for (let i = 0; i < 2 && retryable(r) && this.stats.rewarmups < 6; i++) {
    this.anon = new CookieJar();                    // 整个匿名会话丢弃
    await this.warmup({ force: true });             // 重新预热铸新 d_c0
    await sleep(1200 * (i + 1) + Math.random() * 800);  // 线性退避 + 抖动
    r = await attempt();
}
// 另有全局串行化限速: minIntervalMs=650 + 0~250ms 随机抖动
```

README「能力边界（数据中心 IP 实测）」原表（这是 40362 最珍贵的公开实证）：

| 资源 | 匿名（仅 d_c0+签名） | 备注 |
|---|---|---|
| 文章 `zhuanlan.zhihu.com/p/{id}` | ✅ API 200 | — |
| 回答、问题、热榜 | ❌ 40353 need_login | 注入 z_c0 后走签名通道 ✅ |
| HTML 页面 | ⚠️ **40362** | **__zse_ck 已正确求解，但机房 IP 被声誉层拦截**；住宅 IP / 登录态下 HTML 通道可用 |

**→ 40362 = IP/会话声誉层判定，与 cookie/签名的正确性无关；解法 = 换住宅 IP、上登录态、或重建匿名会话赌新 d_c0。**

### 3.3 srx-2000/spider_collection —— jsdom 派鼻祖（历史形态）

- `g_encrypt.js`：`new JSDOM('<!DOCTYPE html><p>Hello world</p>')`（**不给 url**，默认 `about:blank`），挂 `window/document/XMLHttpRequest` 三个全局。后面是完整的知乎加密 VM（字节码解释器 + 内嵌 base64 程序），导出入口 `b(e) = __g._encrypt(encodeURIComponent(e))`。
- **XHR 处理**：虽然挂了 `XMLHttpRequest = window.XMLHttpRequest`，但加密是同步纯计算，VM 从不发起网络请求。jsdom 的 XHR 挂着不用——这就是「吞」的原始形态。
- `zhihu_answer.py`：`f = "+".join(["101_3_2.0", parse_url, cookie_mes])` → md5 → execjs `b()` → `x-zse-96 = "2.0_" + ...`。cookie 硬编码手填，只抽 `d_c0`。
- 价值：证明**最小环境只要 window/document 两个全局**就能跑官方加密；x-zse-93 版本已老（101_3_2.0），算法骨架未变。

### 3.4 zhihulite/zhihu_zse_ck —— 纯算派的边界实证（2026-10，最新）

不跑任何官方代码，静态分析 wasm 常量池后 Python 直出 `005_` 令牌。对风控信任的三个关键实证（README 原文）：

1. **`__zse_ck = ck(132字符) + '-' + meta(172字符)`**，且「ck 绑定的是 meta 指向的那次挑战的 build 常量，不是 meta 本身……**整条流程必须一次抓取内闭环**」——跨会话缓存 meta 重算 ck 不可行。
2. **位图判据**：`w4 = 0x4000` → 302 真实页；`w4 = 0x4030` → `/account/unhuman`（**token 有效但会话被反标记**）——证明知乎在 token 校验之后还有第二道「环境位图」判定，与 40362 的「声誉层」互为印证。
3. 指纹 = `md5(40 字段)`（hardwareConcurrency / WebGL 厂商渲染器 / canvas.toDataURL / 31 字体 / 5 插件）——这些是沙箱必须补真的环境面。

### 3.5 旁证：Starzzb/zhihu-zse96-v2-python（2026-07）

纯 Python 还原签名（参考 zly2006/zhihu-plus-plus）。README 确认 cookie 最小集共识：**`d_c0` 必需（设备指纹/签名输入）、`z_c0` 可选（搜索等接口强制登录态）**；风控提示仅「HTTP 403 异常请求→控频」，无 40362 专项。

## 4. 四个重点问题的直接回答

**① 各家沙箱的 XHR 处理（吞/桩/真发）**
- **没有任何一家让沙箱真发 XHR**。三档处理：cv-cat「架构层绕开」（JS 只算签名，请求 Python 发）；zhihu-proxy「显式桩死」（`fetch: () => Promise.reject('sandbox fetch blocked')`，产出全靠 `document.cookie` setter 捕获）；srx-2000「挂着不用」（XMLHttpRequest 挂全局但加密纯同步）。
- 可抄结论：**沙箱网络栈桩死是唯一正解；挑战类脚本的唯一合法出口是 `document.cookie` setter 与 `location.reload` 钩子**。

**② 有无「先预热访问首页建立档案再打 API」的标准动作**
- 仅 zhihu-proxy 有，且是强制步骤：`ensureReady()` → 匿名 `GET www.zhihu.com/explore` 拿 `d_c0`/`_zap`/`BEC` → 持久化 `data/session.json` → 后续每个签名请求 `ensureReady` 兜底。cv-cat/srx-2000 都靠用户浏览器复制 cookie 跳过此步。
- 可抄结论：**d_c0 可以匿名预热自铸，不必依赖浏览器**；预热入口 `/explore`（`/signin` 也可 200）。

**③ cookie 罐最小集**
- 共识：`d_c0`（签名必需输入）是唯一硬必需；`_zap`/`BEC` 预热时顺带吸收（无证据必需）；`z_c0` 仅在需要登录态资源（回答/问题/热榜/搜索）时必需；`__zse_ck` 仅走 HTML 页面通道时被挑战强制。
- 最小集 = **`d_c0`（+ `z_c0` 若要登录资源）**。签名用的 d_c0 必须与实际发送的 cookie 一致（zhihu-proxy `dC0With(override)` 专门处理透传场景）。

**④ 有没有谁明确记载「40362 怎么破」**
- **有，且只有 zhihu-proxy**。两重记载：
  - 代码层：`40362/10003` → 丢弃整个匿名 CookieJar → force 重新预热（铸新 d_c0）→ 1.2s×(i+1)+抖动退避 → 重试≤2 次（rewarmups 全局封顶 6）。
  - 实证层（README 能力边界表）：机房 IP 下 `__zse_ck` 已正确求解**仍 40362**——「IP 声誉层拦截」，住宅 IP / 登录态（z_c0）下可用。
- 交叉印证：zhihulite 的 `w4=0x4030 → /account/unhuman`（token 有效但会话反标记）证明第二道判定的存在。
- 可抄结论：**40362 不是签名/cookie 错误，是身份（IP+会话档案）问题；代码对策=换会话重试，根解=换住宅 IP 或上登录态。**

## 6. 风险提示

- cv-cat 的 vendor（other.js，3.7MB heifetz 包）是**快照**，知乎官方升级即失效（zhihu-proxy sign.mjs 有 `tv() 未找到 → vendor 失效` 的显式防御）；走「跑官方 JS」路线必须接受 vendor 维护成本，或学 zhihulite 走纯算（但纯算要随 build 轮换重推常量，维护成本更高）。
- srx-2000 的 `101_3_2.0` 版本号已老，直接照抄会签名失败；以 `101_3_3.0` 为准。
