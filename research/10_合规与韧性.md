# 10 · 知乎抓取工具的合规边界与韧性设计

> 调研日期:2026-11-06 · 工具定位:个人研究用途
> 证据等级标注:【实测】= 本次直接抓取验证;【检索】= 本次搜索引擎结果核实;【知识】= 模型既有法律知识,正式引用前需核对原文
> 检索说明:本机网络 DuckDuckGo 不可达、百度/搜狗反爬、Bing CN 结果降级,主要有效检索通道为 360 搜索(so.com);知乎 robots.txt 为直接 fetch 实测。

## 结论摘要

1. **国内爬虫的红线是"行为+对象+后果"三要素叠加**:绕过/破解技术措施 + 抓取非公开数据或个人信息 + 达到数量/获利门槛 = 刑事(非法获取计算机信息系统数据罪、侵犯公民个人信息罪);仅违反平台意愿但无其他情节,通常止步于民事(违约/不正当竞争)。2024-12 湖南郴州 4 人爬抖音用户信息被判刑、2022 厦门 3 人爬 58 同城被判刑,均为"爬虫软件+批量+商业目的"组合【检索】。
2. **知乎 robots.txt 实测结论(2026-11-06):通用爬虫全站禁止**——`User-agent: * → Disallow: /`(仅放行 `/tardis/jm`);Google-Extended 亦全禁(防 AI 训练)。只对 Google/Bing/百度等具名搜索引擎开放内容页。即:**任何自建 UA 的抓取,在协议层面都不被知乎允许**【实测】。
3. **个人研究安全区**:不绕反爬、不碰他人个人信息、不售卖不公开分发、低频低速、仅抓自己账号可见内容、本地存储 → 落在中低风险区;但它**不是法定豁免**,违反知乎用户协议与 robots 声明,最坏后果是账号封禁 + 民事违约;一旦叠加"绕过技术措施"或"批量抓他人信息",风险立即升级。
4. **工具韧性四件套**:登录态失效检测(探针+错误码识别,失效即停等人工)、挑战识别与人工重过(不做自动打码)、断点续抓(SQLite 任务队列+幂等+死信队列)、健康检查(成功率监控+熔断+令牌桶限速 2-5s/请求+随机抖动)。

## 法律红线与安全区

### 一、刑事红线(绝对不能碰)

| 罪名 | 法条 | 触发行为 | 入罪门槛(司法解释) |
|:--|:--|:--|:--|
| 非法获取计算机信息系统数据罪 | 刑法第285条第2款 | 侵入或**采用其他技术手段**获取系统中存储/处理/传输的数据 | 金融类身份认证信息10组;其他身份认证信息500组;违法所得5000元或造成损失1万元(两高2011年解释)【知识】 |
| 侵犯公民个人信息罪 | 刑法第253条之一 | 非法获取/出售/提供公民个人信息 | 行踪轨迹等敏感信息50条;住宿、通信记录、健康、交易等500条;其他5000条(两高2017年解释)【知识】 |
| 破坏计算机信息系统罪 | 刑法第286条 | 高频抓取致系统故障、删改数据 | 造成系统不能正常运行/严重后果【知识】 |
| 非法侵入计算机信息系统罪 | 刑法第285条第1款 | 侵入国家事务/国防/尖端科技领域系统 | 行为即构罪【知识】 |

**已核实判例**【检索,360 搜索结果】:
- **2024-12,湖南郴州北湖区法院**:朴某、石某、雷某等 4 人成立传媒公司,用爬虫软件批量获取抖音用户个人信息 → 以**非法获取计算机信息系统数据罪**判刑(主从犯区分)。
- **2022-01,厦门**:房麦网络科技有限公司爬取 58 同城房产数据 → 单位+3 名自然人被判非法获取计算机信息系统数据罪。
- 2017 上海晟品网络爬取今日头条视频案(全国首例"爬虫入刑",北京海淀法院)、2017 深圳"车来了"爬取酷米客公交数据案、2019 魔蝎科技案(杭州,判刑 3 年缓刑)——构成均含"**绕过反爬 + 批量 + 商业变现**"【知识,判例细节引用前建议核对裁判文书】。

**共性规律**:入罪的不是"爬虫"这个技术,而是 ①突破技术防护(伪造签名/破解加密/撞库/绕过验证码) ②抓取对象为非公开数据或个人信息 ③数量大或有偿提供 ④对平台造成损害。四条全占几乎必出事;只占第④条的一半(低频)通常无事。

### 二、民事/行政红线

- **《数据安全法》第32条**:收集数据应采取合法、正当方式,不得窃取或以其他非法方式获取数据【知识】。
- **《个人信息保护法》第13、27条**:处理已公开个人信息**限于"合理范围"**,个人明确拒绝的除外;对个人权益有重大影响的须取得同意。→ **批量抓取知乎用户主页/回答中的人身信息(昵称+发言+画像)并建库,即使信息是公开的,也可能越界**【知识】。
- **《反不正当竞争法》**(2025 年修订,2025-10-15 施行)新增数据保护条款:禁止以欺诈、胁迫、**避开或者破坏技术管理措施**等不正当方式获取、使用其他经营者合法持有的数据【知识,条文号建议引用前核对官方文本】。——这把"绕反爬"从技术问题直接升级为法定不正当行为,虽主要约束"经营者",但方向明确。
- **用户协议违约**:知乎协议禁止未经许可的自动化抓取;违反 = 账号封禁 + 违约之诉(对个人研究用户这是最现实的风险)。

### 三、robots 协议的法律地位【检索验证】

- robots.txt **本身不是法律**,违反它不直接构罪;但法院在多个案件中将其作为认定"平台明确意愿/行业惯例"的**证据**:
  - **百度诉 360(3B 大战)**:360 绕过百度 robots 限制强行抓取,结合其签署《互联网搜索引擎服务自律公约》承诺遵守 robots 协议,被认定构成不正当竞争【检索】。
  - **大众点评诉百度(2016,上海浦东法院一审)**:robots 协议成为双方攻防焦点;法院综合抓取方式与使用后果判断正当性【检索,标题级核实,细节建议读判决书】。
  - **微梦(微博)诉字节案,(2021)京民终281号**:入选 2021 年度全国法院知识产权典型案例,系**国内首次对非搜索引擎场景下 robots 协议限制网络机器人行为的正当性作出认定**——即 robots 协议不是单方"法律",其效力结合竞争关系与行为正当性具体判断【检索】。
- **对本工具的含义**:知乎 `* Disallow: /` 是全站拒绝声明。继续抓取不因此单独构罪,但叠加任何绕反爬行为时,robots 声明会成为"明知平台反对仍为之"的证据。

### 四、个人研究用途安全区(可操作建议)

| 维度 | 安全区(做) | 危险区(不做) |
|:--|:--|:--|
| 抓取对象 | 自己账号可见的公开问答/文章/收藏夹 | 他人个人信息批量建库、付费内容、私信、登录后才可见的他人数据 |
| 技术手段 | 自己账号的 cookie 会话、官方导出入口优先 | 破解签名/加密、撞库、自动打码过验证码、IP 池对抗封禁 |
| 速率规模 | ≤0.2-0.5 req/s,总量千级,人工分批 | 高并发、整夜无人值守暴抓、打挂服务器 |
| 数据用途 | 本地阅读/检索/个人笔记,不署名引用原文需标来源 | 售卖、公开发布数据集、建公开镜像站、喂给商用产品 |
| 版权 | 个人学习研究欣赏(著作权法第24条合理使用区间) | 整体性复制再发布、汇编出版 |

一句话:**"自己慢慢看自己存的"是安全区;"替很多人看、给别人看、拿它赚钱"步步升级直至犯罪。**

## 知乎 robots.txt 实测

抓取时间:2026-11-06 04:39 (Asia/Shanghai) · HTTP 200 · 实测原文要点:

```
User-agent: Googlebot / Googlebot-Image / bingbot / Baiduspider(及 -news/-render/-image)
  Allow: /tardis/jm
  Disallow: /appview/  /login  /logout  /resetpassword  /terms  /search
            /notifications  /settings  /inbox  /admin_inbox  /*?guide*
  (百度系额外 Disallow: /en/)

User-agent: AdsBot-Google      → Allow: /en/   Disallow: /
User-agent: Sogou web spider   → Allow: /tardis/sogou/  Disallow: /
User-Agent: Google-Extended    → Allow: /tardis/jm      Disallow: /
User-Agent: *                  → Allow: /tardis/jm      Disallow: /
```

**解读**:
1. **对通用 UA(`*`)全站禁止**,只放行 `/tardis/jm`(知乎的 SEO 预渲染通道)。自建爬虫无论伪装与否,协议层面均属被拒对象。
2. 具名搜索引擎(Google/Bing/百度)可抓内容页,仅禁功能性与账号路径——说明知乎的意图是"内容只给搜索引擎索引用,不给人抓"。
3. `Google-Extended: Disallow: /` = 明确拒绝内容被用于 AI 训练(Google 2023 年推出的 AI 训练 opt-out 标记)。
4. 无 `Crawl-delay` 声明——限速义务全靠自觉;无 Sitemap 指向。
5. robots 声明可随时变更,工具启动时应**每次重新拉取并落盘存档**(既是最新意愿核对,也是合规留痕)。

## 工具韧性设计清单

按"检测 → 应对 → 续抓 → 体检"四层设计,原则是**失效即停、宁慢勿封、断点可续、全程留痕**。

### 1. 登录态失效检测
- **启动探针**:每次任务开始前请求 `GET /api/v4/me`(或轻量账号页),校验 `z_c0` cookie 有效性;返回 401/403/302→`/signin` 即判定失效。
- **运行中检测**:三连判定——(a) HTTP 状态码异常;(b) 响应 URL 被重定向到登录/验证页;(c) 页面 `js-initialData` 为空或结构特征消失。任一触发连续 2 次 → 全局停抓。
- **失效处置**:**停止并通知人工重新登录**,绝不自动重试撞验证(撞验证=触发风控升级);cookie 更新后从断点恢复。
- **预防**:cookie 定期被动刷新(抓取中自然携带),记录 cookie 签发时间与历史寿命,接近经验寿命前主动提醒。

### 2. 挑战/风控重过
- **挑战识别**:知乎风控特征——403 + "安全验证"页、滑块/点选验证码、请求被拦截返回异常短 body。以 URL + 页面标题 + body 长度三重特征判定。
- **应对阶梯**:第一次触发 → 立即降速(间隔 ×4)并暂停 5-15 分钟;仍触发 → 停抓并通知**人工过验证**(保留浏览器通道);当日触发 ≥2 次 → 当日收工。
- **红线**:不接入自动打码平台、不做滑块轨迹模拟——"绕过技术措施"正是入罪要件之一(见上节),工具设计上**主动放弃对抗能力**。

### 3. 断点续抓
- **任务队列持久化**:SQLite(或 JSONL)记录任务清单:目标 ID、类型(回答/文章/收藏夹页)、状态(pending/done/failed/dead)、游标位置、重试次数、错误摘要。
- **幂等写入**:以目标 ID 为主键 upsert,重复抓到不重复存储;正文+元数据+抓取时间戳分行落盘,写坏可整行剔除。
- **恢复语义**:重启后扫描队列,pending 继续、failed(重试<3)重置重试、dead 进死信队列人工过目;收藏夹等列表型任务记录分页游标,从断页续抓。
- **进度可观测**:每次启动打印 待办/已完成/失败/死信 四计数。

### 4. 健康检查与限速
- **限速硬上限**:令牌桶 2-5 秒/请求 + ±50% 随机抖动;夜间不加速;无并发(单线程顺序抓)。个人研究量(千级页面)下,慢是最便宜的保险。
- **成功率监控**:滑动窗口(最近 50 请求)成功率 <90% → 降速;<70% → 熔断停抓,输出诊断(最近 10 条状态码分布)。
- **UA 与指纹**:固定一个诚实、稳定的 UA(建议如实标注个人 bot,如 `personal-research-archiver/0.1`),不轮换伪装——轮换 UA 池属于"对抗封禁"行为模式,与合规目标冲突。
- **结构化日志**:每请求一行(URL/状态码/耗时/字节数),留存可复盘; robots.txt 每次任务拉取存档。
- **合规内建默认值**:抓取范围白名单制(明确指定的问题/收藏夹/自己的内容),默认不抓用户主页信息;字段级过滤(不落地他人联系方式类字段);总量预算制(单任务上限,超出需人工确认)。

## 推荐行动

1. **合规姿态写入 README**:个人研究用途声明 + 不绕过反爬的自我约束 + robots 现状摘录——既是自律清单,也是万一被质疑时的善意证据。
2. **先走官方通道**:能用知乎官方"内容导出/数据备份"功能拿到的,一律不抓;爬虫只补官方不给的部分。
3. **按韧性清单实现四件套**:登录探针、挑战熔断转人工、SQLite 断点队列、令牌桶限速(2-5s+抖动);把"不做自动打码、不做 IP 池"写进设计原则注释。
4. **范围白名单 + 字段过滤**:只抓指定收藏夹/问题/自己的内容;不批量落地他人个人信息;数据仅存本地,不公开发布。
5. **持续监控法律动态**:2025 修订《反不正当竞争法》数据专条的执法案例、知乎 robots/用户协议变更(工具每次启动自动拉取 robots 存档即可顺带监控)。
6. **风险自知**:即使在安全区内操作,知乎仍有权封号;重要账号考虑用小号承载抓取,主号不动。
