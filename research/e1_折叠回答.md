# E1 折叠回答收割 — 端点实测与缺口归因

> 2026-11-06 · 子代理 E1 探测 + 主代理验收补完

## 端点实测结论

**`/api/v4/questions/{qid}/collapsed-answers` 存在且可访问**（FastClient 纯 HTTP，200）。

实测 question 19550225 响应（research/e1_collapsed_raw.json）：
```json
{"paging": {"is_end": false, "totals": 143,
            "next": ".../collapsed-answers?limit=3&offset=3"},
 "data": [null, null, null]}
```

## 关键发现

- 折叠区 **totals=143** 条，但 `data` 返回 **null 桩**——折叠回答的内容不随列表下发
  （这正是「折叠」的产品语义：低质/被踩内容对读者隐藏，API 同样不给全文）
- 缺口归因：**994(feeds 可见) + 143(折叠桩) = 1137**；标称 1528 还差 **391**，
  归因为**已删除/审核中/被建议修改**的回答（不可见内容，任何通道都拿不到）
- 结论：**994 已是该问题的实际可得全量**；折叠区只有计数价值

## harvester.py 增强结论

不值得加 --include-collapsed（拉回的只有 null 桩）。harvester 的 994 即全量。
