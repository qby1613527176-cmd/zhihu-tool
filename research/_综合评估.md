> 2026-11-06 · 10 个子代理并行调研汇总
> 各分报告: `01_知乎CLI生态` `02_签名逆向实现` `03_EdgeOne挑战` `04_反检测框架` `05_TLS指纹` `06_移动端API` `07_RSS与镜像` `08_工程化风控` `09_横向平台对比` `10_合规与韧性`

## 一、总结论

**我们的自建方案（真实浏览器 + 原生签名 + 扫码登录）就是 2026 年的行业事实标准**——
MediaCrawler（70k★，本月仍活跃）与我们架构同构且已支持知乎；纯逆向时代（fuck-login 等）
已于 2023 年后全部死亡。生态上「读+写全功能知乎 CLI」是空位，我们的工具正占此位。

**无需推翻，但有三个明确的补强方向（见行动清单）。**

## 二、跨报告共识

### A. 减重快速通道（最大收获）
x-zse-96 算法本体 **2022 年起 4 年未变**：`"2.0_" + SM4变体(md5("101_3_3.0" + path + d_c0))`
（自定义 S 盒/CBC/自定义 Base64）。开源两派都活着：
- 纯算法端口：zhihu-plus-plus 4.4k★ 血统，~250 行纯 Python 端口（R2）
- 跑官方 JS：HGXY2004/zhihu-proxy，Node vm 沙箱零浏览器，签名 <1ms（R5）

持续迭代的对抗层其实是 2024+ 的 `__zse_ck` WASM PoW（R2/R3）——也能纯 Node 解
（JSDOM 派鼻祖 srx-2000/spider_collection；R3 报告的 RSSHub PR#22319 经 R2 核实有误，
RSSHub 实际走纯 TS 端口 `execlib/x-zse-96-v3.ts`）。

**意义**：日常低频抓取可增开「纯 Node/Python 快速通道」（秒级、无浏览器），浏览器方案做兜底。

### B. 反检测升级（R4）
手写 init-script 是检测链最弱一环（`Runtime.Enable` CDP 泄露盖不住）。
- **原位替换**：patchright / rebrowser-playwright（Playwright drop-in，零代码改动）
- 高危路径：Camoufox（C++ 级指纹 Firefox）
- 淘汰：playwright-stealth / undetected-chromedriver（均停更）

### C. 风控工程化（R8）
核心是「像人」不是「慢」：
- 高斯随机间隔 3–8s（拒绝恒定）；≤10–20 req/min；日预算 ≤3000–8000；01:00–07:00 降速 1/3
- 四级信号熔断：40362 / 429 / 验证码 / 302 跳登录 → 指数退避（1m→5m→30m→2h→当日停），**绝不自动硬刚验证码**
- 新扫码 cookie 有 24–72h 新设备敏感期，期间速率减半
- 账号池抄 CookiesPool 范式（Generator/Tester/API+Redis）；IP 策略：一号一 sticky 住宅 IP，稳定 > 轮换

### D. 先行指标雷达（R7+R2）
watch **RSSHub 仓库 issues/PRs**（知乎反爬变化的早期预警，其路由死亡=风向变了）+
**zhihu-plus-plus**（签名算法变更金丝雀）。

### E. 证伪的路线（不用再试）
- ❌ 纯 HTTP + TLS 指纹伪装（R5：JS 挑战必须执行 JS，curl_cffi 作者自认）
- ❌ 移动端 api.zhihu.com（R6：Bearer + .so 原生签名需 Unidbg，门槛更高且无独有内容）
- ❌ 微博式无签名轻量入口（R9：m.zhihu.com 已 301 到桌面站；日报 API 形同死亡）
- ◐ RSS/镜像（R7：主站路由与直连撞同一堵墙；仅日报/周刊无墙旁路可用）

### F. 合规边界（R10）
- **刑事红线三要素叠加**：绕反爬 + 非公开数据/个人信息 + 数量获利门槛
  （2024 郴州抖音案、2022 厦门 58 同城案）
- 知乎 robots.txt 实测：`User-agent: * Disallow: /` 全站拒抓（仅放行 /tardis/jm）
- 本工具定位的安全区：**低频 + 本地存储 + 不分发 + 不碰他人个人信息**；
  最坏风险止步封号与民事违约。技术上我们确实绕了访问控制——严格讲超出最严安全区定义，
  用途纪律（个人研究、低速率、不分发）是风险压舱石。
